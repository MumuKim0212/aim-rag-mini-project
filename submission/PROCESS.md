- 검색 실패 7문항 중 4문항(POS001, POS006, POS013, POS021)은 정답이 용어집 정의(p.1, 3, 5)인데 약관 청크만 검색됐다. 800자 청크 하나에 용어 약 8개가 섞여 정의 하나의 임베딩이 묻힌다는 사전 점검(1.3절)과 같은 양상이다. 나머지는 여러 페이지 근거(POS052: 02약관 p.1·6), 상황 서술형 질문(ADD-HF10, ADD-SE04)이다
- 확인한 근거 누락 예: ADD-HP09는 정답 p.16(3년 재가입 제한)이 문맥에 없고 p.105만 있다. ADD-SE06은 p.3이 없다. POS050은 03약관 p.5가 없다
- 1점 감점 대부분은 `must_include`의 둘째·셋째 항목, 특히 단서·주의 문장("비교표만으로 확정하지 않는다", "모든 보험으로 일반화하지 않는다")이 빠진 경우다. 채점 이유와 `must_include`를 대조했고 채점 오류로 볼 만한 것은 없었다
- **병목: 근거 부족.** 정답 페이지가 있는 실패 32문항 중 25문항(검색 실패 7 + 근거 일부 누락 13 + 과잉 보류 5)은 필요한 근거 구절이 문맥에 다 들어오지 않았다. 근거가 모두 있는데 불완전한 답은 7문항뿐이다. 다음은 검색 쪽: 청크 크기(001), 구조 단위 청킹(002, 용어집 정의 4문항), 검색 방식(004)
- 답변 쪽 실패(근거 다 있는데 불완전 7, negative 6, 생성 오류 1)는 007(답변 모델)·008(Agent)에서 본다
- **POS054 생성 오류의 원인** (2026-10-21, `scratch/pos054_diag.py`: 저장된 문맥으로 답변 호출만 9회, 약 0.017 USD, 실험 아님)
  - 저장된 기록에는 원본 응답이 없고 `output_tokens` 465·903이 보이는 글자 수(86·151자)와 맞지 않아서, 원본 응답을 캡처했다. `finish_reason=STOP`, 스키마 파싱 성공, 문맥(제24조 전산장애 조항 포함)과 프롬프트도 정상이다
  - 깨진 호출의 원본은 `"answer": "〈ふらい〉 …"`였다. 모델이 한글을 `\uXXXX` 이스케이프로 쓰다가 한글 영역(U+AC00–D7A3)이 아닌 가나 영역(U+3040대) 코드를 골랐다. 이스케이프는 글자당 토큰이 여러 개라서 출력 토큰이 글자 수보다 훨씬 크게 기록된 것도 같은 이유다
  - 재현: 같은 입력·설정(구조화 출력, `gemini-3.5-flash-lite`)에서 5회 중 3회 깨졌다(기준 실행, r2, 진단 1번째). 나머지 2회는 정상 한국어 보류문이었다. 스키마 없이 JSON만 요청한 3회와 같은 입력을 `gemini-3.8-flash`(스키마 있음)로 보낸 3회는 모두 정상이었다. 표본이 작아서 "구조화 출력 + 3.5-flash-lite에서 확률적으로 생긴다"까지만 말할 수 있고, 이 입력의 어떤 점이 이스케이프 모드를 부르는지는 모른다
  - 범위: 기준·r2 180개 실행 중 POS054 2건뿐이다. `scripts/garble_scan.py`(가나 포함 또는 출력 토큰/답변 글자 수 > 2, LLM 없음)로 확인했고 정상 실행은 0.6–1.0, 깨진 2건은 5.4·6.0이다. 이 영향으로 정답 점수 평균이 최대 0.011(1점/90문항) 낮다
  - 관찰(결론 아님): 스키마 없는 3회는 모두 근거를 들어 answered였고, 스키마가 있는 정상 호출 5회 중 4회는 abstained였다. 기준 정답은 답변 가능(`answer_with_citation`)이다
  - 선택지는 (a) 깨짐 감지 시 재시도를 답변 단계에 넣고 기준을 다시 실행 (b) 그대로 두고 답변 실행마다 깨짐 건수를 함께 보고 (c) 이스케이프 금지 문구를 넣은 `answer_v2.md`였다. **(b)로 정했다 (2026-10-21).** 답변 단계를 바꾸면 기준이 바뀌고, 깨짐이 180건 중 1문항이라 영향이 작으며, 007에서 `gemini-3.8-flash`가 깨지지 않으면 답변 모델 선택이 (a)·(c)를 대신하기 때문이다
  - 적용: 007·008을 포함한 답변 실행의 결과를 적을 때마다 `python scripts/garble_scan.py <실험 이름>`의 깨짐 건수를 함께 적는다. 깨진 문항은 점수 비교에서 빼지 않고 그대로 두되, 건수를 밝힌다. 007에서 후보 모델이 깨지는 횟수도 비교 항목으로 본다
