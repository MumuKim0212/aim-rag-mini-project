- 19개(61%)가 "근거가 다 들어왔는데 답이 불완전"이다. 대부분 1점이고, 채점 이유를 읽으면 `must_include`의 둘째·셋째 항목(예외 조항, 비중, 비교 차액)이 빠진 경우다. 검색을 더 고쳐도 줄지 않는 부분이다. 큰 모델(T2)이 이 유형을 더 잘 채운다(T4 열세 13개 중 ADD-HF02 ADD-HF04 ADD-HF08 ADD-SE10 등이 여기 든다).
- T2·T3는 답변 불가 자작 문항에서 본문은 "자료에 빈칸이라 알 수 없다"고 쓰면서 status를 answered로 붙이는 일이 잦았다(SELFB033 SELFB034 SELFB035). 점수는 2점이지만 대응 일치에서는 빠진다. 위 표의 "올바른 대응률"이 T4(0.640)가 T1(0.800)보다 낮은 이유다. T1은 거의 모든 질문에 보류해서 답변 불가 문항에서는 유리하고 답변 가능 문항에서는 15%를 보류한다.

### 6. 개선점

- **검증했지만 효과가 없던 것**: 청크 크기 탐색(카드 001·001b–e, 점수 차이는 오차 범위), BM25 단독(카드 004, 용어 질문에서 오히려 낮음), k=3(카드 005), Agent의 재검색(카드 008: 재검색 9문항, 재검색으로만 찾은 청크를 인용한 건 3문항), 답변 프롬프트 v2의 일반화(카드 010: 개선 8, 악화 6), Agent v2의 답변 검사·1회 고쳐 쓰기와 분류 결과 전달(카드 [014](../experiments/014-agent-v2.md): dev 0.928로 T2와 같음, 짝비교 2 / 2 / 86. 검사 노드가 90문항 중 3문항만 지적했고 겨냥한 불완전 답변 10문항은 하나도 잡지 못했다. 자작 41문항에서도 고쳐 쓴 문항 0. 문항당 비용은 T2의 1.5배).
- **검증하지 않은 아이디어**:
  - 질문 재작성 또는 가상 답변 검색(HyDE): 일상어 질문이 용어집 정의를 못 찾는 유형(SELFB003)을 겨냥. 해당 유형은 test에서 2문항뿐이라 여지가 작다.
  - 답변의 "빠진 항목 점검"을 더 강하게: 카드 014의 검사 노드(일반 규칙만, `gemini-3.8-flash`, thinking low)는 거의 지적하지 않았다. thinking을 높이거나 더 큰 모델을 쓰는 판은 해 보지 않았다. 빠진 것이 채점 기준(`must_include`)의 특정 항목이라 과적합 위험이 있다.
  - status와 본문 일관성 검사(코드): 본문이 "자료에 없음"인데 라벨이 answered인 경우를 잡는다. 대응 일치율이 오를 수 있으나 정답 점수와는 별개다.
  - 채점 모델을 답변 모델과 분리: T2·T3의 자기 채점 편향을 확인하려면 필요하다.

### 7. 평가의 한계

- **잡음**: 같은 설정을 다시 돌리면 90문항 중 14개 답변이 바뀐다(재채점은 3개, PROCESS.md 4절). 한 문항 차이(0.011)는 해석하지 않았다. 각 비교의 신뢰구간으로 판단했다.
- **dev에 맞춘 낙관**: 설정을 dev로 골랐기 때문에 test가 낮다. T2는 dev 0.928 → 제공 test 0.883, T4는 dev 0.894 → 0.844로 둘 다 약 0.05 낮아졌다.
- **test를 두 번 본 부분**: 제공 test 90문항은 T1·T2·T3로 한 번, T4로 한 번 더 봤다. T4를 최종으로 고른 이유는 가격이고 test 점수가 아니다. 다만 T4의 test 수치가 있는 것은 두 번째 실행 덕이라는 점을 밝힌다. 자작 41문항은 네 시스템 모두 한 번씩만 봤다. T4 실행에는 폐기한 첫 자작 세트 20문항도 섞여 돌았지만(채점 포함) 어떤 수치에도 쓰지 않았다.
- **LLM 채점자**: 채점 모델이 T2·T3의 답변 모델과 같다(자기 답변 선호 가능성). 채점 결과 11건을 질문·기준 답안·답변·채점 이유로 대조했다(T4의 SELFB006 013 017 024 029 031 035 041, POS008 POS011, NEG005). 9건은 채점이 맞았다. 틀린 것 1건은 POS011(근거에 있는 숫자를 "출처에 없는 숫자"로 보고 0점, 엄격한 쪽 오류). 나머지 1건 SELFB041은 본문이 기대 대응이고 status 라벨만 달라 채점 규칙(본문 우선)대로 2점이다. 반대로 관대한 채점은 PROCESS.md 2.4절의 NEG034, ADD-IN01 사례가 있다. 누락 항목을 엄격히 세어 1점을 주는 경향이 있다(SELFB013 SELFB017 SELFB031).
- **본문 기준 채점**: status 라벨이 틀려도 본문이 맞으면 점수를 받는다. 라벨 정확도는 "대응 일치율"에서 따로 본다.
- **구조 효과의 전제**: Agent 효과는 rerank가 들어간 검색 위에서 쟀다. 처음 RAG의 검색 위에서는 다를 수 있다. Agent의 새 설정(rerank·v4)은 dev에서 돌려 보지 않고 test에서 바로 한 번 돌렸다.
- **정답 단위**: 정답은 페이지 단위다. 여러 쪽이 정답인 문항은 `evid`(근거 구절 포함률)로 같이 봤다. 조문이 쪽을 넘는 경우 시작 쪽만 정답으로 둔 문항이 있다.
- **문항 특성**: 제공 질문의 약 19%(34문항)는 "이 자료", "그래프"처럼 맥락을 전제한다. 자작 질문은 문서를 읽고 썼지만 짧고 구어체로 썼다. 실제 사용자 질문의 분포와는 다를 수 있다. 제공 positive는 용어 정의형이 많고 근거가 한두 줄이라 쉬운 문항 비율이 높다(PROCESS.md 2.3절).
