# 골든셋 검수 기록

`golden/provided.jsonl`(제공 세트 변환본)을 만들 때 확인한 것과 고친 것을 적는다. 형식은 [README.md](README.md)를 따른다.
`provided.jsonl`은 첫 실행에 쓰이는 순간 고정된다. 이후 수정은 `provided_v2.jsonl`로 만들고 이 문서와 `submission/PROCESS.md` 2절에 적는다.

## 1. 만드는 방법 (2026-10-20)

```
python scripts/convert_golden.py --check   # 대조만, 파일 안 씀
python scripts/convert_golden.py           # golden/provided.jsonl 생성
python -m pytest tests/test_provided_golden.py
```

- 입력: `03_answers/*.jsonl` 180문항(읽기 전용, 수정하지 않음), `corpus/pages.jsonl`(커밋 28064b8, 텍스트 레이어 + 범위 B VLM 보충), 사람이 검수한 근거 구절 `golden/evidence.jsonl`.
- 근거 ID → (파일, 페이지)
  - `fsc-glossary-N`: 용어집 출처 목록(p.20–25)에서 `dicId=N` 줄의 용어를 찾고, 본문(p.1–19)에서 그 용어 줄이 있는 페이지.
  - `kofia-terms-X-V-A`: 약관 1쪽의 `버전: V`로 파일을 찾는다. **A는 조 번호가 아니라 그 약관 출처 목록의 순번**이다(아래 3절). A번째 항목의 조 제목을 본문에서 찾아, 그 조가 걸친 페이지를 본다.
  - `<파일>-pdf-N`, `fss-life-guide-pdf-N`: 그 PDF의 N쪽. 추가 세트의 `source_pages`와 모두 일치했다.
- `targets`: 근거 구절이 있는 페이지. 같은 규정이 다른 문서에 그대로 있으면 `extra_targets`로 추가한다(3절).
- `evidence`: 원문 줄을 그대로 옮긴 구절. 구절마다 `source`(text: PDF 텍스트 레이어, vlm: VLM 보충)를 붙이고, 문항에는 `evidence_source`(text / text+vlm)를 둔다.
- 분할: 시드 `20261020`. 층(stratum)은 세트 × 난이도(negative는 × 유형, 추가 세트는 × 문서). 층마다 섞어서 dev/test를 번갈아 배정한다.
  - 층 크기가 홀수면 1문항이 남는다. 남는 문항을 dev에 줄 층을 세트별·추가 문서별로 절반씩 고르되, 난이도·답변 근거 유형(`context_type`)·negative 유형의 dev/test 차이가 가장 작아지는 조합을 전수 탐색으로 고른다.
  - 그다음 같은 층 안에서 dev 1문항과 test 1문항을 맞바꿔 `context_type` 차이를 없앤다. 층 구성이 그대로라 다른 균형은 바뀌지 않는다.

## 2. 근거 구절 검수

- 답변 가능 148문항(positive 140 + 정정형 negative 8) 전부를 사람이 원문 줄 단위로 골랐다. 자동 선택(기준 답안·`must_include`와 겹치는 문장)은 출발점으로만 썼다. 자동 선택이 근거를 못 찾은 4문항(POS066, ADD-IN03, ADD-IN07, ADD-PF06)은 표 셀이 한 줄씩 추출된 페이지였다.
- 자동 대조: 353구절 전부가 대상 페이지 텍스트와 일치한다(NFKC 정규화 후 공백 제거, `evalkit.metrics.squash`). 모든 정답 페이지가 해당 세트의 검색 범위(A/B) 안에 있고 인덱스 제외 페이지가 아니다.
- 기준 답안 대조: 고른 근거와 기준 답안이 어긋나는 문항은 없었다. 기준 답안·질문 수정 0건(제공 자료는 읽기 전용). 원문 자체가 불일치하는 1건은 3절에 적었다.
- VLM 보충 구절: 표·차트 19문항에 VLM이 정리한 표 행·차트 수치를 근거로 추가했다. 텍스트 레이어에서는 항목명과 값이 다른 줄로 흩어져, 어느 값이 어느 항목인지 텍스트만으로는 알 수 없기 때문이다. 쓴 15쪽을 PDF 페이지 이미지와 대조해 수치가 모두 일치했다.
  - 금융생활 가이드 p.11·22·25
  - 퇴직연금 p.3·4·6·9·21·22
  - 자영업자 채무 p.2
  - 정책서민금융 p.66·82·87·113
  - 보험약관 p.4
  - 주택연금 p.26
  - 해당 문항: POS066, POS067, POS068, POS080, ADD-HP03, ADD-RP04, ADD-RP05, ADD-RP06, ADD-RP08, ADD-RP09, ADD-RP10, ADD-SE02, ADD-SE03, ADD-IN03, ADD-PF02, ADD-PF03, ADD-PF06, ADD-PF07, ADD-PF08.
- 제공 근거 페이지 중 정답 페이지에서 뺀 것: 조문이 다음 쪽으로 이어지지만 답과 무관한 꼬리 부분 4문항(POS027·POS047 06약관 p.6, POS049 01약관 p.3·03약관 p.2, POS060 01약관 p.3).

## 4. 알려진 약점

- 맥락을 전제한 질문 34문항("이 자료", "책에서", "가이드북", "그래프" 등): 금융생활 17, 추가 16, 기본 1. dev 20 / test 14. 제공 질문이라 고치지 않았다. 범위 B에서는 "가이드북"이 금융생활 가이드와 보험약관 이용 가이드북 둘을 가리킬 수 있다.
- 표 숫자만 있는 줄(8자 미만)은 `evidence_segments`에서 빠진다. 표 문항은 VLM 표 행이 항목명과 값을 한 줄에 담아 이를 보완한다. 다만 텍스트 레이어만 들어간 청크에서는 그 표 행이 대조되지 않는다.
- POS079: 학자금대출 비교표가 p.30–31에 걸치고 셀 단위로 흩어져 추출된다. p.31의 VLM 보충은 다른 그림(혼인건수)만 정리했고 p.30은 SKIP이라, 이 표는 텍스트 레이어 조각으로만 근거를 잡았다.
- 답변 불가 32문항(기본 negative)은 정답 페이지·근거가 없다. 검색 지표에서 빠지고 상태(보류·확인·거절) 판정으로만 평가된다. 정정형 negative 8문항은 근거가 있다.
- 정답 페이지가 2개 이상인 문항 71개. `page_hit`은 하나만 찾아도 1이므로, 다중 근거 문항은 `evid`(근거 구절 포함률)로 같이 본다.
- 분할 전에 본 문항: 사전 점검에서 POS001, POS020(dev), NEG001(test)을 실행해 봤다(PROCESS.md 1.3절). NEG001은 test 결과를 해석할 때 이 사실을 적는다.

## 자작 골든셋 `self_v2.jsonl` (2026-10-22)

`self.jsonl`(초안 20문항)은 다른 브랜치의 최종 test 실행에 쓰여 고정됐다(CLAUDE.md: 쓴 골든셋은 고치지 않고 새 버전). 그래서 고친 내용은 `self_v2.jsonl`에 새 qid(`SELF201`~`SELF228`)로 만들었다. 초안의 qid를 다시 쓰면 그 실행 결과와 조용히 어긋난다. 초안과 이어 보려면 각 문항의 `v1_qid`를 본다(SELF2NN ← SELF0NN).
